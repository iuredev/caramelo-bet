2. Architecture

CarameloBet uses a modular monolith style for the .NET backend. The code is split by responsibility instead of putting everything inside controllers.

API: receives HTTP requests and maps endpoints.
Application: holds use cases, DTOs, validators, and abstractions.
Domain: holds business entities and domain behavior.
Infrastructure: implements persistence, repositories, JWT, hashing, email, and external services.
Gateway: YARP reverse proxy, route authorization, rate limiting.

Dependency Direction

Domain
  ^
  |
Application
  ^
  |
Infrastructure
  ^
  |
API / Workers

Gateway is separate and proxies requests to API.

The important idea is that the Application layer defines what it needs through interfaces. Infrastructure implements those interfaces. This keeps business logic independent from EF Core, Resend, BCrypt, and other tools.

How to Decide Where Code Goes

Question Folder
Is it a business object like User or RefreshToken? Domain/Entities
Is it a user action like login, refresh, update profile? Application/UseCases
Is it request or response data? Application/DTOs
Is it input validation? Application/Validators
Is it a contract the app needs? Application/Abstractions
Is it EF Core, JWT, BCrypt, Resend, Redis, RabbitMQ? Infrastructure
Is it HTTP route mapping? API/Endpoints

4. C# Syntax Used So Far

Namespaces

A namespace organizes classes and avoids name conflicts. The project uses file scoped namespaces. 

namespace CarameloBet.Application.UseCases.Auth;

public class LoginUseCase
{
}

Classes

Classes define behavior and state. Use cases, repositories, and services are classes. 

public class LoginUseCase
{
    public async Task<LoginResponse> ExecuteAsync(LoginRequest request)
    {
        // business flow here
    }
}

Primary Constructors

This project uses C# primary constructors for dependency injection. 

public class LoginUseCase(
    IUserRepository userRepository,
    IPasswordHasher passwordHasher,
    IJwtService jwtService,
    IRefreshTokenRepository refreshTokenRepository)
{
    public async Task<LoginResponse> ExecuteAsync(LoginRequest request)
    {
        var user = await userRepository.GetByEmailAsync(request.Email);
    }
}

This is similar to writing a constructor manually, but shorter. 

public class LoginUseCase
{
    private readonly IUserRepository _userRepository;

    public LoginUseCase(IUserRepository userRepository)
    {
        _userRepository = userRepository;
    }
}

Records

Records are good for DTOs because they are simple data carriers. 

public record LoginRequest(
    string Email,
    string Password
);

public record LoginResponse(
    string AccessToken,
    string RefreshToken,
    DateTime AccessTokenExpiresAt,
    AuthenticatedUserResponse User
);

Interfaces

Interfaces define contracts. Application depends on interfaces, not concrete infrastructure classes. 

public interface IUserRepository
{
    Task<User?> GetByIdAsync(Guid id);
    Task<User?> GetByEmailAsync(string email);
    Task AddAsync(User user);
    Task SaveChangesAsync();
}

Nullable Types

The question mark means a value can be null. 

public DateOnly? Birthdate { get; private set; }

public async Task<User?> GetByEmailAsync(string email)
{
    return await context.Users.FirstOrDefaultAsync(user => user.Email == email);
}

Async and Await

Database calls and external service calls are asynchronous. A method returning Task can be awaited. 

public async Task<User?> GetByIdAsync(Guid id)
{
    return await context.Users.FindAsync(id);
}

Generics

Generics let one type work with different data types. The API response wrapper uses this idea. 

ApiResponse<LoginResponse>.Ok(response)
ApiResponse<string>.Ok("Password changed")
ApiResponse<UserProfileResponse>.Ok(profile)

LINQ

LINQ is used to query collections and EF Core data. 

var errors = validationResult.Errors
    .GroupBy(error => error.PropertyName)
    .ToDictionary(
        group => group.Key,
        group => group.Select(error => error.ErrorMessage).ToArray());

Exceptions

Use cases throw exceptions when business rules fail. The global exception handler converts them into HTTP responses. 

if (user is null)
{
    throw new UnauthorizedAccessException("Invalid email or password");
}

5. Domain Layer

The Domain layer contains business entities. It should not know about HTTP, EF Core, PostgreSQL, JWT, or Resend.

Entity Pattern

public class User
{
    public Guid Id { get; private set; }
    public string Name { get; private set; } = string.Empty;
    public string Email { get; private set; } = string.Empty;
    public string PasswordHash { get; private set; } = string.Empty;
    public DateOnly? Birthdate { get; private set; }
    public string Status { get; private set; } = "active";
    public DateTime CreatedAt { get; private set; }
    public DateTime UpdatedAt { get; private set; }

    private User() { }

    public static User Create(
        string name,
        string email,
        string passwordHash,
        DateOnly? birthdate = null)
    {
        return new User
        {
            Id = Guid.NewGuid(),
            Name = name,
            Email = email,
            PasswordHash = passwordHash,
            Birthdate = birthdate,
            Status = "active",
            CreatedAt = DateTime.UtcNow,
            UpdatedAt = DateTime.UtcNow
        };
    }
}

Why Private Setters?

Properties use private set so code outside the entity cannot change state randomly. Changes should happen through named methods. 

public void ChangePassword(string passwordHash)
{
    PasswordHash = passwordHash;
    UpdatedAt = DateTime.UtcNow;
}

public void UpdateProfile(string name, string email, DateOnly? birthdate)
{
    Name = name;
    Email = email;
    Birthdate = birthdate;
    UpdatedAt = DateTime.UtcNow;
}

Token Entities

Refresh tokens and password reset tokens are persisted as hashes. The raw token is only returned to the user or emailed once. 

public class RefreshToken
{
    public Guid Id { get; private set; }
    public Guid UserId { get; private set; }
    public string TokenHash { get; private set; } = string.Empty;
    public DateTime ExpiresAt { get; private set; }
    public DateTime? RevokedAt { get; private set; }

    public bool IsExpired => DateTime.UtcNow >= ExpiresAt;
    public bool IsRevoked => RevokedAt.HasValue;
    public bool IsActive => !IsExpired && !IsRevoked;

    public void Revoke() => RevokedAt = DateTime.UtcNow;
}
Domain rule: business state changes should live on the entity when they are part of the entity behavior.

6. Application Layer

The Application layer coordinates user actions. It does not know how EF Core saves data or how JWT is generated internally.

DTOs

DTO means Data Transfer Object. It is the shape of input or output. 

public record UpdateCurrentUserRequest(
    string Name,
    string Email,
    DateOnly? BirthDate
);

public record UserProfileResponse(
    Guid Id,
    string Name,
    string Email,
    DateOnly? BirthDate,
    string Status,
    DateTime CreatedAt,
    DateTime UpdatedAt
);

Use Case Pattern

A use case is one application action. It receives a request, loads entities, applies business rules, saves changes, and returns a response. 

public class UpdateCurrentUserUseCase(IUserRepository userRepository)
{
    public async Task<UserProfileResponse> ExecuteAsync(
        Guid userId,
        UpdateCurrentUserRequest request)
    {
        var user = await userRepository.GetByIdAsync(userId);

        if (user is null || user.Status != "active")
        {
            throw new UnauthorizedAccessException("Invalid user");
        }

        if (!string.Equals(user.Email, request.Email, StringComparison.OrdinalIgnoreCase)
            && await userRepository.EmailExistsAsync(request.Email))
        {
            throw new ApplicationException("Email already exists");
        }

        user.UpdateProfile(request.Name, request.Email, request.BirthDate);
        await userRepository.SaveChangesAsync();

        return new UserProfileResponse(
            user.Id,
            user.Name,
            user.Email,
            user.Birthdate,
            user.Status,
            user.CreatedAt,
            user.UpdatedAt);
    }
}

Abstractions

Abstractions are interfaces that Application needs. 

public interface IPasswordHasher
{
    string HashPassword(string password);
    bool VerifyPassword(string password, string hashedPassword);
}

This lets tests use fake implementations and production use BCrypt.

Validators

FluentValidation classes validate input before use cases run. 

public class ChangeCurrentUserPasswordRequestValidator
    : AbstractValidator<ChangeCurrentUserPasswordRequest>
{
    public ChangeCurrentUserPasswordRequestValidator()
    {
        RuleFor(input => input.CurrentPassword)
            .NotEmpty();

        RuleFor(input => input.NewPassword)
            .NotEmpty()
            .MinimumLength(6);
    }
}

Dependency Registration

Application use cases are registered in the DI container. 

public static IServiceCollection AddApplication(this IServiceCollection services)
{
    services.AddScoped<RegisterUseCase>();
    services.AddScoped<LoginUseCase>();
    services.AddScoped<RefreshTokenUseCase>();
    services.AddScoped<LogoutUseCase>();
    services.AddScoped<ForgotPasswordUseCase>();
    services.AddScoped<ResetPasswordUseCase>();
    services.AddScoped<GetCurrentUserUseCase>();
    services.AddScoped<UpdateCurrentUserUseCase>();
    services.AddScoped<ChangeCurrentUserPasswordUseCase>();

    return services;
}
Important: use cases should not call EF Core directly. They should go through repository interfaces.

7. Infrastructure Layer

Infrastructure contains details. EF Core, PostgreSQL, BCrypt, JWT, secure tokens, and Resend live here.

DbContext

EF Core uses a DbContext to represent a database session. 

public class AuthDbContext(DbContextOptions<AuthDbContext> options)
    : DbContext(options)
{
    public DbSet<User> Users { get; init; }
    public DbSet<Role> Roles { get; init; }
    public DbSet<Permission> Permissions { get; init; }
    public DbSet<RefreshToken> RefreshTokens { get; init; }
    public DbSet<PasswordResetToken> PasswordResetTokens { get; init; }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.HasDefaultSchema("auth");
        modelBuilder.ApplyConfiguration(new UserConfiguration());
        modelBuilder.ApplyConfiguration(new RefreshTokenConfiguration());
        modelBuilder.ApplyConfiguration(new PasswordResetTokenConfiguration());
        base.OnModelCreating(modelBuilder);
    }
}

Entity Configuration

EF Core configuration maps C# entities to database tables and columns. 

public class UserConfiguration : IEntityTypeConfiguration<User>
{
    public void Configure(EntityTypeBuilder<User> builder)
    {
        builder.ToTable("users");
        builder.HasKey(user => user.Id);

        builder.Property(user => user.Email)
            .IsRequired()
            .HasMaxLength(255);

        builder.HasIndex(user => user.Email)
            .IsUnique()
            .HasDatabaseName("idx_users_email");
    }
}

Repository Implementation

Repositories implement Application interfaces using EF Core. 

public class UserRepository(AuthDbContext context) : IUserRepository
{
    public async Task<User?> GetByIdAsync(Guid id)
    {
        return await context.Users.FindAsync(id);
    }

    public async Task<User?> GetByEmailAsync(string email)
    {
        return await context.Users.FirstOrDefaultAsync(user => user.Email == email);
    }

    public async Task AddAsync(User user)
    {
        await context.Users.AddAsync(user);
    }

    public async Task SaveChangesAsync()
    {
        await context.SaveChangesAsync();
    }
}

JWT Service

The JWT service creates access tokens and refresh tokens. 

public string GenerateAccessToken(
    User user,
    IReadOnlyCollection<string> roles,
    IReadOnlyCollection<string> permissions)
{
    var claims = new List<Claim>
    {
        new(JwtRegisteredClaimNames.Sub, user.Id.ToString()),
        new(JwtRegisteredClaimNames.Email, user.Email),
        new(ClaimTypes.NameIdentifier, user.Id.ToString()),
        new(ClaimTypes.Name, user.Name)
    };

    claims.AddRange(roles.Select(role => new Claim(ClaimTypes.Role, role)));
    claims.AddRange(permissions.Select(permission => new Claim("permission", permission)));

    // create and return signed token
}

Password Hashing

Passwords are never stored as plain text. BCrypt creates a one way hash. 

public string HashPassword(string password)
{
    return BCrypt.Net.BCrypt.HashPassword(password, WorkFactor);
}

public bool VerifyPassword(string password, string hashedPassword)
{
    return BCrypt.Net.BCrypt.Verify(password, hashedPassword);
}

Secure Tokens

Refresh tokens and password reset tokens are random strings. The database stores only hashes. 

public string GenerateToken()
{
    return Convert.ToBase64String(RandomNumberGenerator.GetBytes(64));
}

public string HashToken(string token)
{
    var bytes = SHA256.HashData(Encoding.UTF8.GetBytes(token));
    return Convert.ToHexString(bytes);
}

Infrastructure DI

public static IServiceCollection AddInfrastructure(
    this IServiceCollection services,
    IConfiguration configuration)
{
    services.AddDatabaseContexts(configuration);
    services.AddScoped<IUserRepository, UserRepository>();
    services.AddScoped<IPasswordHasher, PasswordHasher>();
    services.AddScoped<IJwtService, JwtService>();
    services.AddScoped<ISecureTokenService, SecureTokenService>();

    return services;
}
EF Core note: do not run parallel queries with the same DbContext. It is scoped and not thread safe.

8. API Layer

The API layer maps HTTP requests to use cases. This project uses Minimal APIs instead of MVC controllers.

Endpoint Group

public static class UserEndpoints
{
    public static IEndpointRouteBuilder MapUserEndpoints(
        this IEndpointRouteBuilder app)
    {
        var group = app.MapGroup("/api/users")
            .WithTags("Users")
            .RequireAuthorization();

        group.MapGet("/me", async (
            ClaimsPrincipal principal,
            GetCurrentUserUseCase useCase) =>
        {
            var userId = GetUserId(principal);

            if (userId is null)
            {
                return Results.Unauthorized();
            }

            var response = await useCase.ExecuteAsync(userId.Value);

            return Results.Ok(ApiResponse<UserProfileResponse>.Ok(response));
        });

        return app;
    }
}

Validation in Endpoints

Endpoint validation currently follows this pattern. 

var validationResult = await validator.ValidateAsync(request);

if (!validationResult.IsValid)
{
    var errors = validationResult.Errors
        .GroupBy(error => error.PropertyName)
        .ToDictionary(
            group => group.Key,
            group => group.Select(error => error.ErrorMessage).ToArray());

    return Results.ValidationProblem(errors);
}

JWT Claims

Protected endpoints read the current user id from claims. 

private static Guid? GetUserId(ClaimsPrincipal principal)
{
    var userId = principal.FindFirstValue(ClaimTypes.NameIdentifier)
        ?? principal.FindFirstValue(JwtRegisteredClaimNames.Sub);

    return Guid.TryParse(userId, out var parsedUserId)
        ? parsedUserId
        : null;
}

9. Gateway

The Gateway project uses YARP as a reverse proxy. It receives requests and forwards them to the API. 

"ReverseProxy": {
  "Routes": {
    "auth-route": {
      "ClusterId": "api-cluster",
      "Match": {
        "Path": "/api/auth/{**catch-all}"
      },
      "AuthorizationPolicy": "Anonymous"
    },
    "api-route": {
      "ClusterId": "api-cluster",
      "Match": {
        "Path": "/api/{**catch-all}"
      },
      "AuthorizationPolicy": "Default"
    }
  }
}

This means auth routes are public, while other /api routes require a valid JWT at the gateway.

Gateway Middleware Order

app.UseCors("CarameloBetPolicy");
app.UseRedisRateLimiting();
app.UseAuthentication();
app.UseAuthorization();
app.MapReverseProxy();

10. Auth Flow

Register

Client sends name, email, password, and optional birth date.
Validator checks basic input rules.
Use case checks if email already exists.
Password hasher creates a BCrypt hash.
User entity is created.
Repository saves the user.

Login

Client sends email and password.
Use case loads user by email.
Password hasher verifies raw password against stored hash.
JWT service generates access token.
JWT service generates refresh token.
Refresh token is hashed and stored in the database.
Raw refresh token is returned to the client once.

Refresh Token

Client sends refresh token.
Server hashes token and finds matching row.
Server checks token is not expired and not revoked.
Old refresh token is revoked.
New access token and refresh token are generated.
New refresh token hash is stored.

Password Reset

Client sends email.
Use case returns silently if user does not exist.
Secure random reset token is generated.
Token hash is stored in database.
Raw reset token is sent by email.
Client sends token and new password.
Server validates token, changes password, and marks token used.
Security reason: raw refresh and reset tokens are never stored. If the database leaks, attackers cannot use those hashes as tokens.

11. Tests

The Application tests focus on use cases. They use fake repositories and fake services instead of a real database.

Test Shape

[Fact]
public async Task ChangeCurrentUserPassword_WithValidCurrentPassword_ChangesPassword()
{
    var user = User.Create("Iure", "iure@example.com", "hashed-password");
    var useCase = new ChangeCurrentUserPasswordUseCase(
        new FakeUserRepository(user),
        new FakePasswordHasher(true));

        user.Id,
        new ChangeCurrentUserPasswordRequest("current-password", "new-password"));

Fake Repository

private sealed class FakeUserRepository(params User[] users) : IUserRepository
{
    public Task<User?> GetByIdAsync(Guid id)
    {
        return Task.FromResult(users.FirstOrDefault(user => user.Id == id));
    }

    public Task<User?> GetByEmailAsync(string email)
    {
        return Task.FromResult(users.FirstOrDefault(user => user.Email == email));
    }

    public Task SaveChangesAsync()
    {
        return Task.CompletedTask;
    }
}

Why Fakes?

  • Use case tests run fast.
  • They test business flow, not PostgreSQL.
  • They make edge cases easy to simulate.
  • They avoid requiring Docker for every unit test run.
